01 / Data & control flow

先看数据怎么走

点击不同流程，沿着编号从左到右阅读。箭头表示数据或控制关系，并不表示任务按同一个顺序一直运行。

SYSTEM FLOW MAP

从采集、上传到云端控制

SELECT A FLOW

一次采集形成一份快照，再分别交给显示和网络任务。

  1. 01 / INPUT传感器硬件

    DHT11、BMP280、光照 ADC 与 GP2Y1010。

  2. 02 / SENSOR读取与判断

    采样、标记有效状态，比较 PM2.5 阈值并控制蜂鸣器。

  3. 03 / SNAPSHOT写入两条队列

    两份长度为 1 的快照分别供显示和网络使用。

  4. 04 / OUTPUTS显示 / 上报

    Display 更新 OLED；NetworkTask 读取另一份快照，等待上报。

注意第 04 步包含两条并行分支：显示任务不会先执行完，网络任务才允许执行。

模块接收 AT 指令的结果，与云平台是否接受数据，是两次不同的确认。

  1. 01 / FORMAT组装属性报文

    读取上传队列，只加入本轮有效传感器字段。

  2. 02 / SEND发送 MPUB

    串口发送 AT 指令，限时等待模块 OK；接收仍在进行。

  3. 03 / RECEIVEDMA 接收消息

    中断通知网络任务；等待期间也会处理完整行。

  4. 04 / MATCH匹配平台回执

    按主题、消息 ID 和 code 判断本次上报结果。

  5. 05 / RESULT显示结果

    上传结果进入队列，显示任务更新联网状态页。

注意平台回执与模块 OK 的到达顺序可能不同；等待平台回执期间，网络任务仍可处理下发。

云端设置经过同一条串口接收路径，解析后更新本地报警配置。

  1. 01 / ONENET发起属性设置

    下发 PM2.5 阈值或声音允许开关。

  2. 02 / UART RX模块输出 MSUB

    DMA 保存字节；空闲、半满或满等接收事件通知任务。

  3. 03 / QUEUE分流并排队

    网络任务拼行，识别设置主题，写入下发队列。

  4. 04 / APPLY更新配置

    解析并覆盖报警配置队列，采集任务下轮读取。

  5. 05 / REPLY回复请求 ID

    网络任务发送 set_reply，平台收到结果。

注意开关为“允许超限时发声”；打开开关不会强制蜂鸣器立即响。

连接异常时只让网络任务进入恢复流程，本地任务仍由调度器运行。

  1. 01 / DETECT发现异常

    超时、串口错误或状态异常满足恢复条件。

  2. 02 / MARK标记待恢复

    取消未完成的等待；失败事件保留，旧下发可能丢弃。

  3. 03 / WAIT延时后重试

    失败后等待约 5 秒；不在循环中一直占用 CPU。

  4. 04 / RECOVER重同步与连接

    必要时重启 DMA，等待串口安静，查询并重建连接。

  5. 05 / RESUME重新订阅与上报

    连接成功后重新开始周期上传和状态查询。

边界模块 RST 未确认接入 STM32；模块完全死机时，软件不能保证自动复位。

INSIDE ONE SENSOR CYCLE

把一轮采集展开

按照 Sensor() 中的先后顺序，从左到右阅读。

顺序示意 · 宽度不代表耗时
  1. 01 / DHT11温湿度起始信号拉低期间等待约 20 ms，再读取。
  2. 02 / BMP280气压触发测量，释放总线等待约 20 ms，再读取。
  3. 03 / ADC光照连续读取 16 次，计算平均值。
  4. 04 / GP2Y粉尘100 次预热 + 16 次采样，约 10 ms 一次。
  5. 05 / UPDATE判断与发布更新报警、事件及两份数据快照。
  6. 06 / DELAY等待 2 秒本轮完成后阻塞，让其他就绪任务运行。

DHT11 起始的 20 ms、BMP280 测量的 20 ms 与粉尘采样间的 10 ms 使用任务延时，可以让出 CPU；微秒级等待与短临界区仍会占用 CPU。失败时，对应流程可能提前结束。

TASK 01 / ACQUISITION

采集任务

PRIORITY 2STACK 384 WORDS

TASK 03 / CONNECTIVITY

网络任务

函数 NetworkTask() · 模块通信的唯一业务入口

PRIORITY 1STACK 512 WORDS

网络任务负责模块连接、AT 事务、属性 / 事件上报和云端设置。等待回复时通过任务通知阻塞，让出 CPU。

01
连接与订阅

初始化 DMA，执行模块配置、TCP / MQTT 登录和主题订阅。

02
上传与事件

取最新快照组包；超限事件在收到成功回复后出队。

03
接收与下发

在任务中拼接串口文本、识别平台回执和属性设置。

04
超时与恢复

串口错误、超时或状态异常可触发恢复；失败后等待再试。

main.c / NetworkTask()air780e.conenet_connect.conenet_upload.c

启动任务 · StartTask / P3

主程序先初始化硬件并显示约 5 秒启动页；启动任务再创建通信对象与三个业务任务，随后删除自身。

空闲任务 · Idle / P0

由 FreeRTOS 创建，在没有更高优先级任务可运行时执行，也负责回收已删除任务的部分资源。

怎么看优先级？ FreeRTOS 任务优先级数字越大越高，所以 Sensor 的 2 高于 Display 和 NetworkTask 的 1。两个 P1 任务同时就绪时可以按时间片轮转；实际顺序还取决于它们是否正在等待队列、通知或互斥锁。
04 / Queues & synchronization

任务之间靠什么配合？

队列传递快照、结果和事件；互斥锁保护共享总线。中断负责通知，不在中断里解析 JSON。

CREATE创建与删除

xTaskCreate() 创建任务；启动任务完成后 vTaskDelete()。

DELAY等待与让出

vTaskDelay() 用于任务等待；粉尘采样用 vTaskDelayUntil() 控制间隔。

QUEUE数据交接

xQueueOverwrite() 更新快照；接收或窥视由各自任务完成。

SYNC互斥与通知

信号量互斥访问 I²C；串口中断用任务通知唤醒网络任务。

05 / Notes & source

几个容易绕晕的地方

把流程图和代码对应起来，也把当前方案的边界保留下来。

快速理解

为什么需要两个快照队列？

显示任务和网络任务各自需要一份最新数据。两个长度为 1 的队列分别保存副本，避免一个消费者取走数据后，另一个消费者没有数据。

DMA 和空闲中断是不是一个任务？

不是。DMA 由硬件搬运接收字节；中断记录事件并通知网络任务。Air780E_ReadLine() 和消息解析在网络任务中执行。

AT 的 OK 就是平台上传成功吗？

不是。模块的 OK 说明对应 AT 命令收到模块确认；还需要匹配 OneNET 回执的主题、消息 ID 和返回码，才能判断平台结果。

上传时下发能立刻执行吗？

等待 AT 响应时，网络任务仍会读取串口并把符合条件的下发暂存到队列；真正执行设置和回复需要等当前 AT 事务结束。连接较慢或队列满时，下发仍可能超时或丢失。

高优先级任务会一直独占 CPU 吗？

不会。采集任务读取过程里有延时，整轮结束也会等待；处于阻塞状态时，显示和网络任务可以运行。两个 P1 任务的执行顺序取决于就绪状态和调度。

现在的数据都一定准确、可恢复吗？

PM2.5 是未标定的旧公式估算值；ADC 成功不能证明模拟传感器供电正常。阈值、蜂鸣器设置和未发送事件不做掉电保存。
