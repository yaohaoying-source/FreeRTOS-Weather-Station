# 裸机版风速采集代码（修正后的历史参考）

这些文件基于本项目的旧版裸机工程整理，仅供后续移植时查阅，**没有加入当前 FreeRTOS 的 Keil 工程或编译流程**。当前固件尚未实现风速采集、显示、上报和风速阈值报警。

已使用 Arm Compiler 5 和旧工程头文件单独编译两份 C 文件；尚未链接至当前固件，也未进行实板验证。

| 文件 | 来源与内容 |

| [adc.c](adc.c) | 基于旧版 `mycode/adc/adc.c` 修正引脚配置和采样返回值检查；它同时服务于旧版其他模拟传感器。 |

## 旧版处理方式

`Get_Wind_Data()` 调用 `get_Adc_Average(3, 10)`：读取 ADC 通道 3 共 10 次，每次采样后延时 5 ms，再按旧公式换算；小于 2.28 的结果置零。旧主循环将结果保存到 `wind`，在 OLED 上以 `m/s` 显示，并将风速与 `wind_thr` 比较参与报警。旧工程默认 `wind_thr = 5`。

这里保留的是原始经验公式，**不代表已经完成校准**。风速模块具体型号、输出范围与公式适用性仍需结合实物确认。

## 对旧版参考代码的修正

- 旧业务读取 ADC 通道 0、1、3，但旧驱动初始化了 PA5、PA6；这里将初始化及反初始化改为与通道相对应的 PA0、PA1、PA3。当前 CubeMX 也将 PA3 配置为 `ADC1_IN3`。
- 采样时检查 ADC 启动、等待和停止的返回状态；平均次数为 0 时直接返回，避免除零。
- 为保持旧接口，采样失败仍返回 0，因此无法区分故障和真实零值，多次平均也可能包含失败样本。后续移植时应使用独立的成功状态，并决定如何处理失败样本。

## 以后移植时需要核对

- 旧 ADC 代码依赖旧工程中的 `main.h`、`sys.h`、`delay.h`、HAL 以及 `u8` / `u32` 类型，还定义了 ADC 初始化和 HAL 回调。直接加入新工程可能与已有实现冲突。
- 后续有时间再核对传感器供电、输出电压、接线与换算关系，接入采集任务及有效性判断，并按需要补充 OLED、云端上报和风速报警；完成后再进行实板验证。
